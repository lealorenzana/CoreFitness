# Simplify the Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One way to do each thing: personal training (single sessions + monthly packages) is the only coaching;
classes, squads, events and season are off by default but fully working when a gym turns them on; groups,
non-package rooms, class rooms and Friends are removed.

**Architecture:** One migration (0219) changes the switches' default, deletes what was removed and narrows rooms to
packages; then the coach app (the Discord rail kept, holding Today, Personal training and package trainees), the member app (Train/You/Rewards/More) and the admin app (one Personal
training page) are reshaped on the data that already exists. Every removed screen's route redirects to its new home.

**Tech Stack:** Supabase Postgres (pasted by hand), React 19 + Router v7 + TS (member app: Tailwind v4, admin:
Tailwind v3), pglite SQL harness, Playwright fixture checks (`scripts/ci/run-ui-checks.mjs`).

**Spec:** `docs/superpowers/specs/2026-10-28-simplify-design.md` · mock-up `docs/superpowers/specs/2026-10-28-simplify/mock-simplify.html` (approved 2026-10-28).

## Global Constraints

- Removed, with their data, hard delete: coaching groups + group packages; rooms of single-session trainees; class rooms; Friends (0217) entirely.
- Off for every gym now, owner can switch on: `classes`, `squads`, `seasons`, `events` (new key, child of `push`).
- **When switched on, each must work inside the new structure** (owner: "align everything so nothing will break, even the turned off features").
- Names: members see **Coach**; coach and admin apps say **Personal training**; the noun "booking" appears on no screen (a *session* is one appointment; "Book a session" is a verb).
- Rooms exist only for packages; a package's room opens on the chat (Chat · Classwork · Progress · About).
- The coach app keeps its Discord design (rail, bottom panel, You sheet) — owner, 2026-10-28.
- Chat stays for single-session trainees.
- All three ways to start a package stay (member asks, coach offers, desk assigns).
- A redesign never drops a feature beyond the removals above; old routes and notification `action_url`s redirect.
- CLAUDE.md rules hold: RLS is the boundary; revoke new helpers from public; per-member caches in `memberCaches.ts`; violet = state, amber = action, never a fixed violet inside a gym; type floor 12px; `minmax(0,1fr)`.
- Migrations: marker granted to anon, `scripts/sql/verify/verify0219.sql`, probe entry, CI suite line, pglite harness; Privacy and What's new notes change in the commit that changes the rule.
- After each part: build, lint the changed files, run the checks, commit, push, deploy the changed app, confirm the new code is in the live bundle.

## Review Focus

1. **Old links** — `/member/friends*`, `/member/rooms*`, `/member/booking-history`, `/trainer/bookings`, `/trainer/rooms*`, `/trainer/members`, `/trainer/coaching`, `/trainer/availability` (bookmarks and old notification rows) land on the new home, never a blank page.
2. **A gym turns Classes back on** — class requests show on the coach's Today, classes in Schedule and in Train, admin class pages return, kiosk class check-in works, and no screen looks for a class room.
3. **A package ends** — its room stays readable (archived), and `sync_gym_rooms()` neither deletes nor recreates it.
4. **Empty states** — a coach with nobody yet, a member with no package and no sessions: every tab says what to do, none is blank.
5. **Offline outbox** — a queued room post or comment for a room the migration deleted is refused and dropped with a toast, not retried forever.
