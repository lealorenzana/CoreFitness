# Deployment & the installable phone app

How Core Fitness ships to real phones at **$0** — no domain purchase, no Play Store fee,
no Apple Developer account.

## The shape of it

The member/trainer app is a **PWA** (installable web app) deployed to Vercel's free tier. The
Android `.apk` is a **TWA** (Trusted Web Activity) — a thin native shell generated by
[PWABuilder](https://www.pwabuilder.com) that loads the live Vercel URL.

**The APK does not bundle a copy of the app.** Redeploying to Vercel updates every installed
phone automatically; users never reinstall. Only these require regenerating the APK:

- app name or icon
- package ID
- manifest `start_url` or `scope`

iPhone has no $0 sideload path (Apple blocks it). iOS users install via Safari →
**Add to Home Screen**, which the `apple-mobile-web-app-*` meta tags in `index.html` make
launch full-screen with the right icon.

## Live URLs

| What | URL |
|------|-----|
| **Member/trainer app (canonical)** | **`https://corefitness-gym.vercel.app`** |
| Auto-generated fallback | `https://core-fitness-zatanaels-projects.vercel.app` |
| Vercel project | `zatanaels-projects/core-fitness` |

`corefitness-gym.vercel.app` is the address baked into the APK — **use it everywhere**. Changing
it later means regenerating the APK and re-hosting `assetlinks.json`.

⚠️ `core-fitness.vercel.app` and `core-fitness-app.vercel.app` are **other people's apps**, not
this project. Verify any deploy by checking the page `<title>` and manifest, never by HTTP status
— an unrelated SPA returns 200 for every path too.

## Deploying

Only `g-fitness-member/` is deployed. The admin dashboard stays local/desktop (it's used on a
laptop during the defense).

```bash
cd g-fitness-member && npx vercel deploy --prod --yes
```

The Vercel project is already linked (`.vercel/` in `g-fitness-member/`) and
`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` are set for production/preview/development.
Only the **publishable** key is ever deployed — verified absent from the bundle: no
`sb_secret_*` value, no service-role JWT.

### Two settings that bite

- **Deployment Protection must stay OFF.** Vercel enables "Vercel Authentication" by default on
  new projects, which redirects every visitor to a Vercel login page — phones can't install an
  app they must log into Vercel to reach. Symptom: `curl` returns HTTP 200 but the page title is
  `Login – Vercel`. Fix: project Settings → Deployment Protection → Vercel Authentication →
  Disabled → **Save** (the toggle alone doesn't persist).
- **[vercel.json](../g-fitness-member/vercel.json)** provides the SPA rewrite (all paths →
  `index.html`) so React Router deep links don't 404 on refresh, plus correct `Content-Type` for
  the manifest and a no-cache header for `sw.js`.

## PWA setup

Configured via `vite-plugin-pwa` in [vite.config.ts](../g-fitness-member/vite.config.ts).

- **Icons** are generated from `public/logo.png` (600×600) — `pwa-192x192.png`,
  `pwa-512x512.png`, `maskable-icon-512x512.png`, `apple-touch-icon-180x180.png`. The logo has
  transparent corners, so all icons are composited onto the `--color-bg` (`#0F0F1A`) background.
  The **maskable** icon keeps the logo inside the inner ~62% safe zone, or Android's circular
  crop cuts off "FITNESS".
- **Precache is deliberately the app shell only** (11 entries, ~1.2 MB): JS/CSS/HTML/SVG + the
  PWA icons. Gym/trainer photos run to 2 MB+ each and are excluded — workbox will hard-fail the
  build on anything over 2 MB rather than silently skipping it.
- **Supabase responses are never cached.** A stale membership status or QR payload is worse than
  an honest offline error, hence `runtimeCaching: []` and the `supabase.co` navigate-fallback
  denylist. `OfflineBanner` tells the user why data screens are empty.

## The responsive phone chassis

[PhoneChassis.tsx](../g-fitness-member/src/components/layout/PhoneChassis.tsx) owns the decorative
375×812 frame and decides whether to draw it:

- **Desktop browser (≥768px, not installed)** → full chassis with fake notch/status bar, for
  demoing the app as a phone on a laptop during the defense.
- **Real phone or installed PWA** (`display-mode: standalone`, or viewport <768px) → chassis
  removed, app fills the screen using `100dvh` + `env(safe-area-inset-*)`.

Both `Layout.tsx` (authenticated) and `MobileFrame.tsx` (login/terms/privacy) delegate to it.

**The portal roots (`#phone-screen`, `#phone-toast-root`, `#phone-overlay-root`, `#modal-root`)
must exist in both branches** — pages portal into them by id, so dropping one silently breaks
toasts and modals in that mode only.

`index.html` needs `viewport-fit=cover` for the safe-area insets to resolve.

## The Android app (already generated)

| | |
|---|---|
| Package ID | `app.vercel.corefitness_gym.twa` — **permanent**; changing it makes Android treat it as a different app, so existing installs can never update |
| Signing cert SHA-256 | `51:A4:C8:DB:D3:D4:B9:7E:B3:1E:29:4E:68:5F:81:82:E9:63:B3:8C:B1:2A:9C:78:31:6E:E1:66:9D:FD:7D:26` |
| Keystore | `signing.keystore` + `signing-key-info` from the PWABuilder zip — **kept by the owner, not in this repo** |

Domain association lives at [public/.well-known/assetlinks.json](../g-fitness-member/public/.well-known/assetlinks.json)
and is verified live by Google:

```bash
curl -s "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://corefitness-gym.vercel.app&relation=delegate_permission/common.handle_all_urls"
```

`statements` non-empty and `errorCode` absent means the app opens with no URL bar. Vite does copy
the dot-directory from `public/` into `dist/`, and Vercel serves it ahead of the SPA rewrite —
both were verified, but re-check them if the file ever 404s or returns HTML.

## Regenerating the APK

1. https://www.pwabuilder.com → enter `https://corefitness-gym.vercel.app` → **Start**
2. **Package for stores** → **Android** → **Download Package**
3. Reuse the **existing signing key** — a new key means installed users must uninstall and
   reinstall to update. Back up the `.keystore` and its password permanently.
4. Host the generated `assetlinks.json` at `public/.well-known/assetlinks.json` and redeploy.

`assetlinks.json` is what proves the app and the domain belong together. Without it the TWA
still runs but shows a browser URL bar instead of looking native.

Sideloaded APKs trigger Android's "install from unknown sources" prompt — expected, and free.
